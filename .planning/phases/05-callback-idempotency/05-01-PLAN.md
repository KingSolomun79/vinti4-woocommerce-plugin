Add a new public static method `build_response_fingerprint()` to the `Vinti4_Fingerprint` class (after the existing `build_request_fingerprint()` method).

The method recomputes the SISP response fingerprint so it can be compared against the `resultFingerPrint` POST field.

**Method signature:**
```php
public static function build_response_fingerprint(
    string $pos_auth_code,
    string $message_type,
    string $clearing_period,
    string $transaction_id,
    string $merchant_ref,
    string $merchant_session,
    string $purchase_amount,
    string $message_id,
    string $pan,
    string $merchant_response,
    string $timestamp,
    string $reference_number,
    string $entity_code,
    string $client_receipt,
    string $additional_error_message,
    string $reload_code
): string
```

**Algorithm** (must match SISP specification exactly):
```
$base = sha512_base64(posAuthCode)
     + messageType
     + clearingPeriod
     + transactionID
     + merchantReference
     + merchantSession
     + (int)(purchaseAmount * 1000)
     + messageID
     + pan
     + merchantResponse
     + timestamp
     + reference
     + entity
     + clientReceipt
     + additionalErrorMessage
     + reloadCode

return sha512_base64($base)
```

**Implementation notes:**
- Use `self::sha512_base64()` for both the posAuthCode hash and the final hash — same primitive as the request fingerprint.
- The `(int)(purchaseAmount * 1000)` means: cast the purchase_amount string to int, multiply by 1000, then cast to string for concatenation. Follow the same pattern as the request fingerprint: `(string) ( absint( $purchase_amount ) * 1000 )`.
- All other fields are trimmed before concatenation, matching the request fingerprint pattern.
- The PHPDoc should document the SISP response field each parameter maps to (e.g., `merchantRespCP`, `merchantRespTid`, etc.).
