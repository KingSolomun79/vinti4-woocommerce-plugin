  <action>
Create `includes/class-vinti4-callback-handler.php` with a `Vinti4_Callback_Handler` class.

**File header:** Standard plugin file header — `defined( 'ABSPATH' ) || exit;` guard, class_exists guard (same pattern as `class-vinti4-fingerprint.php` and `class-vinti4-request-builder.php`).

**Class: `Vinti4_Callback_Handler`**

Single public static method:

```php
public static function handle( WC_Gateway_Vinti4 $gateway ): void
```

**Step 1 — Extract and validate POST data:**
- Read `$_POST` (with `// phpcs:ignore WordPress.Security.NonceVerification` comment — no nonce for SISP callbacks, SISP is an external server).
- Extract required fields into local variables:
  - `$message_type` from `$_POST['messageType']`
  - `$result_fingerprint` from `$_POST['resultFingerPrint']`
  - `$merchant_ref` from `$_POST['merchantRespMerchantRef']`
  - `$merchant_session` from `$_POST['merchantRespMerchantSession']`
  - `$purchase_amount` from `$_POST['merchantRespPurchaseAmount']`
  - `$clearing_period` from `$_POST['merchantRespCP']`
  - `$transaction_id` from `$_POST['merchantRespTid']`
  - `$message_id` from `$_POST['merchantRespMessageID']`
  - `$pan` from `$_POST['merchantRespPan']`
  - `$merchant_response` from `$_POST['merchantResp']`
  - `$timestamp` from `$_POST['merchantRespTimeStamp']`
  - `$reference_number` from `$_POST['merchantRespReferenceNumber']`
  - `$entity_code` from `$_POST['merchantRespEntityCode']`
  - `$client_receipt` from `$_POST['merchantRespClientReceipt']`
  - `$additional_error_message` from `$_POST['merchantRespAdditionalErrorMessage']`
  - `$reload_code` from `$_POST['merchantRespReloadCode']`
  - `$error_detail` from `$_POST['merchantRespErrorDetail']`
  - `$error_description` from `$_POST['merchantRespErrorDescription']`
- Use `sanitize_text_field( wp_unslash( ... ) )` for string fields. Use empty string fallback `''` for optional fields.
- If `$merchant_ref` or `$result_fingerprint` is empty, call `wp_die()` with generic error and exit.

**Step 2 — Parse order ID and load order:**
- `$order_id = vinti4_parse_order_id_from_ref( $merchant_ref )`
- If `$order_id` is 0, `wp_die()` with 'Invalid merchant reference' (400)
- `$order = wc_get_order( $order_id )`
- If order not found, `wp_die()` with 'Order not found' (404)

**Step 3 — Validate merchantRef matches stored meta:**
- `$stored_ref = $order->get_meta( '_vinti4_merchant_ref' )`
- If `$stored_ref !== $merchant_ref`, the callback is for a different attempt — redirect to checkout with `wp_safe_redirect( wc_get_checkout_url() ); exit;`

**Step 4 — Idempotency check:**
- `$already_processed = $order->get_meta( '_vinti4_callback_processed' )`
- If truthy, the callback was already handled. Redirect to the appropriate page:
  - If order has status 'processing' or 'completed': `wp_safe_redirect( $order->get_checkout_order_received_url() ); exit;`
  - Otherwise: `wp_safe_redirect( wc_get_checkout_url() ); exit;`

**Step 5 — Determine success vs failure:**
- `$is_success = vinti4_is_success_message_type( $message_type )`

**Step 6 (if success) — Validate response fingerprint:**
```php
$expected_fingerprint = Vinti4_Fingerprint::build_response_fingerprint(
    $gateway->pos_auth_code,
    $message_type,
    $clearing_period,
    $transaction_id,
    $merchant_ref,
    $merchant_session,
    $purchase_amount,
    $message_id,
    $pan,
    $merchant_response,
    $timestamp,
    $reference_number,
    $entity_code,
    $client_receipt,
    $additional_error_message,
    $reload_code
);
```
- If `$expected_fingerprint !== $result_fingerprint`:
  - `$order->update_status( 'failed', __( 'Vinti4 fingerprint validation failed.', 'vinti4' ) )`
  - `$order->update_meta_data( '_vinti4_callback_processed', '1' )`
  - `$order->save()`
  - `wp_safe_redirect( wc_get_checkout_url() ); exit;`

**Step 7 (if success) — Validate amount:**
- `$stored_amount = (int) $order->get_meta( '_vinti4_amount' )`
- `$response_amount = (int) $purchase_amount`
- If `$stored_amount !== $response_amount`:
  - `$order->update_status( 'failed', __( 'Vinti4 amount mismatch.', 'vinti4' ) )`
  - `$order->update_meta_data( '_vinti4_callback_processed', '1' )`
  - `$order->save()`
  - `wp_safe_redirect( wc_get_checkout_url() ); exit;`

**Step 8 (if success) — Complete the order:**
- `$order->payment_complete( $transaction_id )` — this is the ONLY completion call. Do NOT call `update_status('completed')`, `reduce_order_stock()`, or `WC()->cart->empty_cart()`. WooCommerce handles stock reduction and cart emptying via `payment_complete()`.
- `$order->add_order_note( sprintf( __( 'Vinti4 payment authorized. TID: %s', 'vinti4' ), $transaction_id ) )`
- `$order->update_meta_data( '_vinti4_callback_processed', '1' )`
- `$order->save()`
- `wp_safe_redirect( $order->get_checkout_order_received_url() ); exit;`

**Step 9 (if failure) — Mark order failed:**
- `$order->update_status( 'failed', sprintf( __( 'Vinti4 payment failed: %s - %s', 'vinti4' ), $error_detail, $error_description ) )`
- `$order->update_meta_data( '_vinti4_callback_processed', '1' )`
- `$order->save()`
- `wp_safe_redirect( wc_get_checkout_url() ); exit;`

**CRITICAL CONSTRAINTS:**
- NEVER call `$order->reduce_order_stock()` — `payment_complete()` handles this
- NEVER call `WC()->cart->empty_cart()` — WooCommerce handles this
- NEVER call `$order->update_status('completed')` — use `payment_complete()` instead
- Always set `_vinti4_callback_processed` meta before redirecting (for idempotency)
- All redirects use `wp_safe_redirect()` followed by `exit`

<task type="auto">
  <name>Task 2: Add private helper for setting callback processed meta and redirecting</name>
  <files>includes/class-vinti4-callback-handler.php</files>
  <action>
Refactor the repeated pattern of "set meta → save → redirect → exit" into a private static helper method on the same class.

**Add this private method:**

```php
private static function mark_processed_and_redirect( WC_Order $order, string $redirect_url ): void {
    $order->update_meta_data( '_vinti4_callback_processed', '1' );
    $order->save();
    wp_safe_redirect( $redirect_url );
    exit;
}
```

Then replace all occurrences in `handle()` where the pattern `$order->update_meta_data( '_vinti4_callback_processed', '1' ); $order->save(); wp_safe_redirect( ... ); exit;` appears with a call to `self::mark_processed_and_redirect( $order, $url )`.

This should result in 4-5 call sites being consolidated:
1. Fingerprint validation failure → redirect to checkout
2. Amount mismatch → redirect to checkout
3. Success completion → redirect to order received
4. Failure → redirect to checkout

The idempotency redirect (step 4) does NOT set meta (it was already set), so it should NOT use this helper — it stays as direct redirect + exit.
