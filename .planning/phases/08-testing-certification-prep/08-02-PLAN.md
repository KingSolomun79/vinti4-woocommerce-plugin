**PART A — Admin Diagnostic Panel:**

Create `includes/class-vinti4-admin-test-panel.php` with class `Vinti4_Admin_Test_Panel`.

This class provides an admin page under WooCommerce that runs self-tests. Architecture:

1. `register()` — hooks into `admin_menu` to add a submenu page:
   - Parent slug: `woocommerce`
   - Page title: "Vinti4 Diagnostic Tests"
   - Menu title: "Vinti4 Tests"
   - Capability: `manage_woocommerce`
   - Slug: `vinti4-tests`
   - Callback: `render_page()`

2. `render_page()` — renders the test page:
   - If `$_POST['vinti4_run_tests']` is set (nonce verified), run tests and display results
   - Otherwise show a "Run Tests" button in a form
   - Results display as a table: Test Name | Status (Pass/Fail) | Details
   - Use WordPress admin styling (admin_notice classes for pass/fail colors)

3. `run_tests()` — returns array of test results. Each result: `['name' => string, 'passed' => bool, 'details' => string]`

Tests to run (these verify WP-dependent behavior on the live installation):

a. **Config Present Test**: Check gateway has pos_id, pos_auth_code, vbv2_url configured. Pass if all non-empty.

b. **Logger Available Test**: Check `wc_get_logger()` returns a logger instance. Pass if not null/false.

c. **Fingerprint Hash Test**: Call `Vinti4_Fingerprint::sha512_base64('test')` and verify it returns a non-empty base64 string that decodes to 64 bytes (SHA-512 = 64 bytes). This proves the hash function works in the WP environment.

d. **Currency Map Test**: Create a gateway instance, call `get_currency_code()` on a mock order (or verify the static map is accessible). Check that 'CVE' maps to '132'.

e. **Success Types Test**: Call `vinti4_is_success_message_type()` for '8', '10', 'M', 'P' (all true) and '0', '1' (all false).

f. **Logger Mask Test**: Call `Vinti4_Logger::mask_auth_code('ABCDEFGHYZ')` and verify result equals `'ABC***YZ'`.

g. **Logger Mask Empty Test**: Call `Vinti4_Logger::mask_auth_code('')` and verify result equals `''`.

h. **Callback Endpoint Test**: Verify the rewrite rule for `vinti4-payment` is registered by checking `get_option('rewrite_rules')` contains the pattern. If not found, report as warning (rewrite rules may need flushing).

i. **Gateway Registered Test**: Verify `WC_Gateway_Vinti4` is in the list returned by `WC()->payment_gateways()->payment_gateways()`.

j. **Blocks Support Test**: Check if `WC_Vinti4_Blocks_Support` class exists (it should if the plugin is loaded).

k. **Callback Simulation Test — Duplicate Detection**: Create a test order with `_vinti4_callback_processed` meta set to '1'. Verify the callback handler rejects it without changing order status.

l. **Callback Simulation Test — Invalid Fingerprint**: Create a test order, simulate callback POST with success messageType but wrong fingerprint. Verify order is marked failed.

Style the page with WordPress admin CSS classes. Use `submit_button()` for the run button. Use `wp_nonce_field('vinti4_run_tests', 'vinti4_tests_nonce')` for CSRF protection.

Important: The test panel is loaded ONLY in admin context. Add a guard: `if ( ! is_admin() ) return;` in `register()`.

**PART B — Wire admin panel into gateway:**

Edit `includes/class-wc-gateway-vinti4.php` to load the test panel:
- In the gateway constructor (or admin_init hook), if `is_admin()`, require_once the test panel class and call `Vinti4_Admin_Test_Panel::register()`.
- Best approach: Add `add_action('admin_init', ...)` in the constructor to load and register the panel.

Read the current gateway class first to find the right insertion point.
