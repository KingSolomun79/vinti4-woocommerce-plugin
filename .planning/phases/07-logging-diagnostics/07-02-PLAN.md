  <name>Task 1: Add logging to request builder and gateway process_payment</name>
  <files>includes/class-vinti4-request-builder.php, includes/class-wc-gateway-vinti4.php</files>
  <action>
Two files to modify:

**1. `includes/class-vinti4-request-builder.php` — `build_payment_attempt()` method**

Add a logging call AFTER the return array is built (after line 90, before the return statement). Log the attempt data with masked auth code. The log message should be structured as multi-line for readability:

```php
Vinti4_Logger::log( sprintf(
    "Payment attempt built:\n  attempt_id: %s\n  order_id: %d\n  merchantRef: %s\n  merchantSession: %s\n  timestamp: %s\n  amount: %s\n  currency: %s\n  transaction_code: %s\n  posAuthCode (masked): %s\n  fingerprint: %s",
    $attempt_id,
    $order->get_id(),
    $merchant_ref,
    $merchant_session,
    $timestamp,
    $amount,
    $currency,
    $transaction_code,
    Vinti4_Logger::mask_auth_code( $gateway->pos_auth_code ),
    $fingerprint
) );
```

Place this AFTER the `$fingerprint` variable is computed and the return array is assigned, but BEFORE the `return` statement.

**2. `includes/class-wc-gateway-vinti4.php` — `process_payment()` method**

Add a logging call INSIDE the config validation block (the `if ( empty( $this->pos_id ) || empty( $this->pos_auth_code ) || empty( $this->vbv2_url ) )` check, line 209), right before the `wc_add_notice` call:

```php
Vinti4_Logger::log( 'Payment attempt blocked: gateway configuration incomplete (missing pos_id, pos_auth_code, or vbv2_url).', 'error' );
```

Use level 'error' because this is a configuration problem that prevents payment.

<task type="auto">
  <name>Task 2: Add logging to callback handler at each validation step</name>
  <files>includes/class-vinti4-callback-handler.php</files>
  <action>
Add `Vinti4_Logger::log()` calls at every decision point in the `handle()` method. Each log entry must include enough context to identify the order and the specific issue. Use the following placement and messages:

**A. Callback receipt** — Add as the FIRST thing in `handle()`, right after the `$post = $_POST;` line (line 58), before any sanitization:

```php
Vinti4_Logger::log( 'Callback received from SISP.' );
```

**B. Invalid callback data** — Inside the `if ( empty( $merchant_ref ) || empty( $result_fingerprint ) )` block (line 80-82), before the `wp_die`:

```php
Vinti4_Logger::log( 'Callback rejected: missing merchantRef or resultFingerprint.', 'warning' );
```

**C. Invalid merchant reference** — Inside the `if ( 0 === $order_id )` block (line 87-89), before the `wp_die`:

```php
Vinti4_Logger::log( sprintf( 'Callback rejected: could not parse order ID from merchantRef "%s".', $merchant_ref ), 'warning' );
```

**D. Order not found** — Inside the `if ( ! $order )` block (line 93-95), before the `wp_die`:

```php
Vinti4_Logger::log( sprintf( 'Callback rejected: order %d not found.', $order_id ), 'error' );
```

**E. Merchant reference mismatch** — Inside the `if ( $stored_ref !== $merchant_ref )` block (line 100-104), before the redirect:

```php
Vinti4_Logger::log( sprintf( 'Callback rejected: merchantRef mismatch. Stored: "%s", Received: "%s".', $stored_ref, $merchant_ref ), 'warning' );
```

**F. Duplicate callback** — Inside the `if ( $already_processed )` block (line 109-117), before the redirect:

```php
Vinti4_Logger::log( sprintf( 'Duplicate callback detected for order %d (already processed). Redirecting.', $order_id ) );
```

**G. Fingerprint validation failed** — Inside the `if ( $expected_fingerprint !== $result_fingerprint )` block (line 143-146), before the status update:

```php
Vinti4_Logger::log( sprintf( 'Callback rejected for order %d: fingerprint mismatch. merchantRef: %s, messageType: %s.', $order_id, $merchant_ref, $message_type ), 'error' );
```

**H. Amount mismatch** — Inside the `if ( $stored_amount !== $response_amount )` block (line 152-155), before the status update:

```php
Vinti4_Logger::log( sprintf( 'Callback rejected for order %d: amount mismatch. Stored: %d, Response: %d.', $order_id, $stored_amount, $response_amount ), 'error' );
```

**I. Payment success** — After `$order->payment_complete()` (line 160), before the order note:

```php
Vinti4_Logger::log( sprintf( 'Payment completed for order %d. TID: %s, merchantRef: %s, messageType: %s.', $order_id, $transaction_id, $merchant_ref, $message_type ) );
```

**J. Payment failure** — In the failure path (line 172-181), before the status update:

```php
Vinti4_Logger::log( sprintf( 'Payment failed for order %d. messageType: %s, errorDetail: %s, errorDescription: %s.', $order_id, $message_type, $error_detail, $error_description ), 'warning' );
```

This gives 10 distinct log points covering every branch of the callback handler, each with enough context to diagnose issues.
