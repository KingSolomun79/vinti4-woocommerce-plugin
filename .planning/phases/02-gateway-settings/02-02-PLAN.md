  <action>
    Add a new public method `get_currency_code( $order = null )` to the gateway class. Place it AFTER `process_admin_options()` and BEFORE `process_payment()`.

    The method:
    1. If an order is provided (WC_Order instance), get its currency via `$order->get_currency()`
    2. If no order or order currency is not in the known mapping, fall back to `$this->get_option( 'currency_default', 'CVE' )`
    3. Map the ISO 4217 alpha code to numeric code using a static array
    4. Return the numeric code as a string (SISP expects string like '132')

    Implementation:

    ```php
    public function get_currency_code( $order = null ) {
        $currency_map = array(
            'CVE' => '132',
            'EUR' => '978',
            'USD' => '840',
            'AOA' => '973',
            'BRL' => '986',
            'GBP' => '826',
        );

        $currency = '';

        if ( $order && is_a( $order, 'WC_Order' ) ) {
            $currency = $order->get_currency();
        }

        if ( empty( $currency ) || ! isset( $currency_map[ $currency ] ) ) {
            $currency = $this->get_option( 'currency_default', 'CVE' );
        }

        return isset( $currency_map[ $currency ] ) ? $currency_map[ $currency ] : '132';
    }
    ```

    Key design decisions:
    - Final fallback is '132' (CVE) if somehow the currency_default setting is also unmapped
    - `is_a( $order, 'WC_Order' )` check prevents errors if null or wrong type passed
    - Returns string, not int — SISP protocol uses string numeric codes
    - Currency map includes CVE (primary), EUR, USD, AOA (Angolan Kwanza — secondary market), plus BRL and GBP as common WooCommerce currencies. More can be added later without architectural changes.
