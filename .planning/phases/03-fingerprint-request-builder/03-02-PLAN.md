**1. `public static function build_payment_attempt( WC_Order $order, WC_Gateway_Vinti4 $gateway ): array`**

This is the canonical entry point that produces all data needed for a SISP redirect.

Implementation:
```php
public static function build_payment_attempt( WC_Order $order, WC_Gateway_Vinti4 $gateway ): array {
    $timestamp        = vinti4_format_timestamp();
    $attempt_id       = wp_generate_uuid4();
    $merchant_ref     = vinti4_build_merchant_ref( $order->get_id() );
    $merchant_session = vinti4_build_merchant_session();
    $transaction_code = '1';  // Authorization
    $amount           = (string) vinti4_normalize_amount( (float) $order->get_total() );
    $currency         = $gateway->get_currency_code( $order );

    $purchase_request_json = self::build_purchase_request_json( $order );
    $purchase_request_b64  = base64_encode(
        wp_json_encode( $purchase_request_json, JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES )
    );

    $fingerprint = Vinti4_Fingerprint::build_request_fingerprint(
        $gateway->pos_auth_code,
        $timestamp,
        $amount,
        $merchant_ref,
        $merchant_session,
        $gateway->pos_id,
        $currency,
        $transaction_code,
        '', '', ''
    );

    return array(
        'attempt_id'           => $attempt_id,
        'timestamp'            => $timestamp,
        'merchant_ref'         => $merchant_ref,
        'merchant_session'     => $merchant_session,
        'transaction_code'     => $transaction_code,
        'amount'               => $amount,
        'currency'             => $currency,
        'purchase_request_b64' => $purchase_request_b64,
        'fingerprint'          => $fingerprint,
    );
}
```

**2. `private static function build_purchase_request_json( WC_Order $order ): array`**

Builds the 3DS purchaseRequest JSON from order/customer data. This is Base64-encoded and sent to SISP as part of the redirect POST.

Fields to populate (use WooCommerce order methods):
- `acctID` — `$order->get_customer_id()` (0 for guest)
- `email` — `$order->get_billing_email()`
- `addrMatch` — `'Y'` if billing and shipping addresses match, `'N'` otherwise (compare billing_address_1, city, postcode, country)

Billing address block (from `$order->get_billing_*()`):
- `billAddrCity` — billing city
- `billAddrCountry` — billing country (ISO 3166-1 alpha-2, 2 chars)
- `billAddrLine1` — billing address 1
- `billAddrLine2` — billing address 2 (can be empty)
- `billAddrLine3` — empty string (SISP expects field but WC has no line 3)
- `billAddrPostCode` — billing postcode
- `billAddrState` — billing state

Shipping address block (from `$order->get_shipping_*()`):
- `shipAddrCity` — shipping city (empty if no shipping)
- `shipAddrCountry` — shipping country (empty if no shipping)
- `shipAddrLine1` — shipping address 1 (empty if no shipping)
- `shipAddrPostCode` — shipping postcode (empty if no shipping)
- `shipAddrState` — shipping state (empty if no shipping)

Phone block (use `vinti4_shape_phone()`):
- `workPhone` — array with `cc` and `subscriber` from billing phone
- `mobilePhone` — same structure from billing phone (WC doesn't distinguish)

Account info block (best-effort from WC data):
- `acctInfo` — array with:
  - `chAccAgeInd` — `'05'` if registered customer with older account, `'01'` if guest (no account). Use `($order->get_customer_id() > 0) ? '05' : '01'`
  - `chAccDate` — empty string (WC doesn't track account creation date in order context)

CRITICAL RULES:
- **NO `purchaseDate` field** — deprecated by SISP, must not appear
- Keep optional fields as empty strings rather than inventing values
- All address strings should be trimmed
- Phone numbers shaped via `vinti4_shape_phone()`
- Return a plain PHP array (caller handles JSON encoding + Base64)
