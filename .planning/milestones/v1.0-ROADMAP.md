# Milestone v1.0: Vinti4 for WooCommerce MVP

**Status:** ✅ SHIPPED 2026-04-16
**Phases:** 1-8
**Total Plans:** 15

## Overview

Complete rewrite of the Vinti4 WooCommerce payment gateway from a brittle legacy adaptation into a modern WooCommerce payment extension. The plugin integrates with SISP to process card payments via a hosted 3DS redirect flow. This v1 focuses on stability, standards-alignment, and fingerprint reliability — creating a clean base for v2 tokenization.

## Milestone Summary

**Key Decisions:**

- Gateway ID is `vinti4` (string, not numeric) — PRD specifies stable string ID
- Hosted redirect flow (not API) — SISP uses redirect-based payment
- No Composer dependencies — eliminated `sokil/php-isocodes`, use built-in WP/Woo functions
- Settings in WooCommerce → Payments (not separate admin menu)
- purchaseRequest without `purchaseDate` (deprecated by SISP)
- Use `payment_complete()` for order completion (WooCommerce handles stock reduction)
- Callback via `woocommerce_api_{gateway_id}` (no standalone PHP callback files)
- Auth code sanitization via wp_unslash() only (preserve % + / =)
- Static builder methods for fingerprint, request builder (no instance state needed)
- Plain JS IIFE for block registration (no build step)
- PHPUnit with WP stubs (no WordPress installation needed for tests)

**Issues Resolved:**

- Legacy gateway ID was numeric `2424` → string `vinti4`
- No dependency guards → class_exists() guard + admin notice
- Direct gateway instantiation → filter-based registration
- Brittle wp-load.php includes → woocommerce_api endpoint
- No callback idempotency → _vinti4_callback_processed meta protection
- Raw SQL on uninstall → settings option deletion only
- Pages created on activation → no page creation
- Deprecated purchaseDate field → removed from purchaseRequest JSON
- Composer dependency → eliminated, static currency map
- No logging → structured debug logging with auth code masking

**Issues Deferred:**

- Tokenization (TOK-01 through TOK-04) — v2 scope
- Admin capture/void/refund (ADM-01 through ADM-03) — v2 scope
- WooCommerce Subscriptions compatibility (SUB-01) — v2 scope

**Technical Debt Incurred:**

- None significant — all code follows WordPress/WooCommerce standards
