## End-to-End Flow Verification

### Flow 1: Admin Partial Payment Flow

1. Admin opens order edit page -> sees outstanding balance + paid total
2. Admin enters partial amount (fixed or percentage) -> clicks Create
3. JS sends AJAX to `vinti4_create_partial_request` -> handler validates amount
4. Handler calls `$gateway->create_payment_attempt()` -> Factory creates unique attempt
5. Store appends to attempt history + projects legacy meta -> payment link returned
6. Admin copies link -> sends to customer
7. Customer opens link -> Redirect Form reads projected legacy meta -> renders SISP 3DS form
8. Customer pays on SISP -> callback to `woocommerce_api_vinti4`
9. Handler resolves attempt via `find_attempt_by_merchant_ref()` -> validates session/fingerprint/amount
10. `mark_attempt_completed()` -> partial payment note on order -> order stays processing

**Status:** ✓ Complete — all 10 steps wired and verified statically

### Flow 2: Multi-Attempt Full Payment

1. Admin creates first partial payment (e.g., 60%) -> customer pays
2. Callback resolves attempt -> `mark_attempt_completed()` -> outstanding > 0.01 -> order stays processing
3. Admin sees updated outstanding balance -> creates second payment for remaining 40%
4. Customer pays -> callback resolves second attempt
5. `get_paid_total()` now equals order total -> outstanding <= 0.01 -> `payment_complete()` called
6. Order marked complete, stock fully reduced

**Status:** ✓ Complete — outstanding threshold logic verified in callback handler

### Flow 3: Legacy Card Checkout Flow (Backward Compatibility)

1. Customer checks out with Vinti4 (classic or block)
2. `process_payment()` creates attempt via factory + appends to history + projects legacy meta
3. SISP redirect -> customer pays -> callback arrives
4. Handler finds attempt via `find_attempt_by_merchant_ref()` (returns non-null for v1.1 orders)
5. Attempt-level path processes callback -> `payment_complete()` if full amount
6. **Pre-v1.1 orders:** no attempt history -> legacy fallback -> order-level validation -> completes

**Status:** ✓ Complete — both v1.1 and pre-v1.1 order paths verified

### Flow 4: Resend Payment Link

1. Admin sees pending attempt in history table with status badge
2. Admin clicks Resend link -> JS calls `vinti4ReprojectAttempt`
3. Handler calls `project_latest_attempt_to_legacy_meta()` for that attempt
4. Payment link returned -> copied to clipboard via `navigator.clipboard.writeText()`
5. Customer opens link -> sees payment form with correct attempt context

**Status:** ✓ Complete — reproject + clipboard chain verified
